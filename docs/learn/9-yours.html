🛠️ Make it yours

Everything in these lessons is yours to change: the robot's code, the remote, the 3D robot, the pretend room. This last lesson gets you your own copy of the whole project, with your own website and your own update page.

🧰 You need

  • A free GitHub account. (A grown-up's job: GitHub accounts are for people aged 13 and over.)
  • For the second half: a computer with Python 3 and Node.js 20 or newer. Nothing else gets installed.

▶️ Your own copy, with its own website

  1. Open github.com/gabeduke/alvik and press Fork. Now you have a copy that is yours.
  2. In your copy: Settings, then Pages, and set Source to GitHub Actions.
  3. Open the Actions tab and allow workflows to run.
  4. Change something small that you will see. On GitHub, open docs/index.html, press the pencil, find <span id="title"> Alvik</span> and put your robot's name in place of Alvik. Commit it.
  5. Wait about a minute, then open https://YOUR-NAME.github.io/alvik/. That is your remote, with your robot's name at the top. Its 🔧 page puts your code on the robot.

Every time you commit a change, GitHub runs the project's tests, builds the site and puts it online. If a test fails, nothing is put online, so a mistake can't reach the robot that way. Look in the Actions tab to see what happened.

The tests know the robot's numbers. Change SPEED or a light colour and a test will fail on purpose. Read what it says: it names what else has to change with it, like a lesson that quotes the old number, or the pretend robot's copy. Change those too (or the test, if you meant it) and it goes online.

💻 Work on it on your own computer

git clone https://github.com/YOUR-NAME/alvik
cd alvik
scripts/build_site.sh && python3 -m http.server -d _site 8000    # then open http://localhost:8000

node --test tests/*.test.mjs       # the page's side
python3 tests/test_robot.py        # the robot's side, on a pretend Alvik

Bluetooth and USB both work from localhost, so you can drive the real robot from the copy on your computer. There is nothing to install and no build tool: the site is plain files, and the build script only copies them.

🧪 Things to change, easiest first

  • Rebuild the pretend room. At the top of docs/pretend.js is ROOM: the walls, the box, the mats and the tape, in centimetres. Add a mat in your favourite colour. Add a maze (a test drives the pretend robot straight at the box, so leave that path clear or change the test).
  • New light colours. COLORS in remote_control.py is the list the 💡 button steps through. The pretend robot keeps a copy in docs/pretend.js.
  • A new dance. src/dance.py is short: lights that change on a beat, a wiggle, a spin. The pretend robot has a copy of that too.
  • Tune the 3D robot. docs/sensing.js has the numbers for the heat's colours, how far a lift raises it, and what counts as a dark line.
  • Paint the 3D robot. The model is built by a script, models/build_alvik_web.py, from Arduino's own drawing of the Alvik and a LEGO-style top plate by GiulioT. The plate's licence (CC BY-NC-SA) asks you to keep the credit and not to sell it. models/README.md has the details.
  • A whole new sensor. Give it a new packet letter (lesson 7 says why). Four places change together: the robot builds the packet in remote_control.py, the page reads it in telemetry.js, an example goes in tests/telemetry_vectors.json so both are tested against it, and twin.js draws it.

🚀 Where next

The project's own list of ideas is in its GitHub issues: tricks like a figure-eight, a LEGO arm on a servo, eyes on a little screen, and skins so kids can design their own 3D robot.

If you build something, or find a mistake in a lesson, open an issue there and say so.
